# Insight Engine Git Workflow

Streamline your development by using this structured Git workflow.

## 1. Structured Commits
Use the **Conventional Commits** format:
- `feat`: A new feature
- `fix`: A bug fix
- `docs`: Documentation only changes
- `style`: Changes that do not affect the meaning of the code (white-space, formatting, etc)
- `refactor`: A code change that neither fixes a bug nor adds a feature
- `perf`: A code change that improves performance
- `test`: Adding missing tests or correcting existing tests
- `chore`: Changes to the build process or auxiliary tools and libraries

**Format**: `<type>(<scope>): <description>`
Example: `feat(broker): add full support for Dhan API`

## 2. Automated PR Creation
When creating a PR using `gh pr create`:
- **Title**: Match the commit message format.
- **Body**: Use a template that includes:
  - **Summary**: What was changed.
  - **Related POA**: Reference the milestone from `FINAL_POA.md`.
  - **Testing**: How it was verified.

## 3. Branch Management
- **Main**: Stable branch.
- **Feature Branches**: `feat/feature-name`.
- **Bug Fixes**: `fix/bug-name`.

## Workflow Command Examples
- **Commit**: `git commit -m "feat(api): add JWT token rotation"`
- **Push & PR**: `git push origin <branch> && gh pr create --title "feat(api): add JWT token rotation" --body "Implements Milestone 3.1 of FINAL_POA.md"`
- **Cleanup**: `gh pr list --state closed` to find branches to delete.
